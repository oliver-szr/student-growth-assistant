## 实际机制

1. 分别读取正式两周快照和有效待确认草案。任务身份使用 task/draft ref；正式差异不再把上一份未确认候选当作正式基线。
2. 对选定的剩余任务检查原未来片段的完整时长、DDL、网格、工作窗口、规则及锁定要求。本轮新增/编辑/明确指定重新安排的任务、原片段不再合法的任务进入受影响范围。
3. 合法且未受影响的未来任务在输入副本中临时 `locked=True`，不写回 TaskSchedulingProfile。正式历史、已开始和已有锁定继续受到原机制保护；已完成任务不重新分配剩余工作。显式解锁沿用原有确认流程。
4. 调用原 `arrange` 与独立校验器，保持均衡 `(4,3,3)`、习惯 `(6,2,2)`、稳定 `(2,6,2)` 权重。新增移动数、片段数、配对位移、重叠比只用于观察，不改变原评分；冻结范围减少无关任务移动，不宣称全局最少移动或全局最优。
5. 失败不产生部分可确认计划。普通未找到完整方案时，若存在可放开的合法任务，才展示扩大范围建议。SEARCH_LIMIT 保留搜索预算含义；不会直接称为数学无解，也不自动扩大。
6. 用户通过 preview 的独立请求明确允许后，才让其他可移动未来任务参与。AI 的 ParsedCommand 没有扩大授权字段，临时阻塞、偏好或策略输出也不会授予扩大权限。授权仅沿同版本草案链继承，放弃、采用或版本变化后重置。
7. 结构化分组按完整片段集合和 ref 计算，显示保留/移动/新增/待处理及移除；切换候选同步分组与指标。错过的任务如果缺少剩余证据，待处理时长为 null，历史仍保留，不把经过的时间认定为完成。
8. 课程/保护冲突的解释由实际展开的区间生成，包含任务引用、原区间、阻塞区间、真实规则 ID 和类别。临时内存约束另标来源，不冒充持久规则。DDL、锁定、时间推进和工作要求变化有基本中文事实说明；AI 不可用时仍可使用。

局部范围目前以整个任务的剩余片段集合为单位；不尝试只移动同一任务内部的某一片段。已开始任务按既有保守语义冻结其全部未来片段。

## 确认与安全

- 正式快照的 ref、标题、起止时间集合计算稳定 SHA-256 摘要。范围元数据另在已有 AssistantMessage.content 记录摘要标记；不是新增表或安全密钥。
- 同步消息、preview 编辑/扩大和异步 AI 运行均保存标记。新候选的元数据被改变或移除时拒绝，不能退回旧候选兼容逻辑；无标记且无元数据的历史候选继续使用阶段 0 校验。
- confirm 核对消息标记、扩大来源、版本和正式摘要，按当前数据重新识别冻结范围并比较片段；随后继续阶段 0 的正式历史核对、重复锁定防绕过、当前时间复验和完整计划校验。
- 两周仍一次事务写入。第二周插入故障的测试验证第一周、任务与版本整体回滚；确认前、拒绝、放弃和失败均不覆盖正式计划。已采用方案重复确认仍幂等。
- 摘要是内部一致性防线，不能防御能够同时任意改写多个数据库表的攻击者。旧入口 `/api/plans` 的安全拒绝和复验机制保持不变。

## API 与数据

不新增端点。messages 增加 `replan=false`；为 true 可无 actions 且不调用 AI。preview 增加 `expand_scope=false`，只可独立用于最新同版本的局部失败候选。无效扩大返回 422 INVALID_SCOPE_EXPANSION；范围/快照/授权变化使用 409 STALE_CANDIDATE。

响应增量提供 replanning、change_groups、formal_plan_needs_review，以及候选 option 的分组和移动指标。旧 changes 和选项结构保留。响应详细字段、指标分母和诊断来源见 [API 契约](../docs/api-contract.md)。

没有 models、数据库表、Alembic 或冻结基线修改，因此无迁移。元数据复用现有 JSON 列；导出/恢复测试证明范围和消息标记被保留，恢复后候选仍失效，不能复活授权。正常 app.db、个人数据和 .env 未修改；演示/测试库、日志、截图均被忽略，不进入 Git。

## 已知限制与下一阶段

- 原有界启发式仍可能错过可行方案；搜索失败/预算不足都有明确提示。扩大仍需用户确认，不自动放宽 DDL、时长、网格、工作窗口或保护约束。
- 单用户全局 revision 继续让无关数据修改使候选失效。范围授权是当前草案链内部语义，没有新增权限系统。
- 按任务整体剩余片段和正式位置冻结；对已有正式任务，建议先采用新位置再锁定，避免把尚未确认的位置当作正式锁定基线。大量任务、复杂分段和压力场景尚未系统评测。位移指标采用排序配对，新增/删除片段不能被误读为严格匹配最短距离。
- AI 自然语言解释质量没有真实模型验收；程序事实说明和手动核心流程已验证。历史任务缺少反馈时仍需用户明确核对剩余量。
- 原演示启动脚本仍有历史 `.venv` 路径，本阶段没有为跑演示创建 venv 或改写该脚本，使用显式 app_env 启动隔离实例。正常开发继续遵守 README 的 Conda 命令。

满足本阶段核心验收后，可进入阶段 2 的任务拆解设计；任务层级需要继续保留 ref 身份、剩余工作证据、备份引用完整性与统一确认校验。需要用户另行给出阶段 2 任务，本阶段结束后停止。
