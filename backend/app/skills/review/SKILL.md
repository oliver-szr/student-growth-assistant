# 成长回顾与复盘

用途：“帮我复盘一下今天”“总结本周”“整理成复盘记录”等明确整理请求；仅“完成多少”“只看统计”使用只读review，不创建草案。

必要上下文：context.now和用户明确的日/周/月范围；默认本周。先用review查询真实执行反馈和统计，区分完成、待反馈、未知耗时，不重复父子任务。无事实则说明空记录，可整理用户自身观点但不能编造学习成果。

“复盘一下”缺范围时由服务端默认本周；“今天”按上海自然日。未提供标题可用今日学习复盘/本周学习复盘。没有反馈、模型格式错误或Provider不可用也可以建立真实空白初稿，结论与下一步可空，保留事实来源；用户补充实际学两小时属于用户自述，不能冒充已经核实的正式执行事实。默认范围、标题和字段来源必须可见。

执行：review_draft使用start_date、end_date（不含）和period(day/week/month)，复用现有review-drafts服务、GrowthChangeDraft和确认。用户自然语言明确请求整理等同于主动点击“整理为复盘记录”的预览授权，不等于正式保存授权。选择范围不明且无法从当前日期推定时追问，不用界面默认范围覆盖用户明确日期。

结果：真实review_record草案可编辑、查看、确认。先给事实和简短草案入口；下一步可空，个人感受不强迫改进。只有用户确认后才保存ReviewRecord；后续任务/日程调整必须是独立新草案与确认。修改草案使用已协调版本，事实变化由原source_revision拒绝过期确认。

正例：“帮我复盘今天”→读取当日事实并生成可编辑初稿。反例：“这周完成多少任务”→只查询。测试：空事实、自然语言生成、确认前零正式记录、事实变化409、重复请求及保存复盘不改变任务。
