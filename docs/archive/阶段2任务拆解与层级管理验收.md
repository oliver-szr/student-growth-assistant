## 交付行为

1. 规划页新增“复杂任务拆解”：输入任务、明确 DDL、原始预期与可选目标；AI 生成结构化建议，或使用无需 AI 的手动空草案。
2. 用户可编辑父子标题、说明、时长、DDL，增删子任务、上下调整建议顺序。实时显示总量及与原始预期之差。合法编辑暂停1.2秒后自动保存，也提供显式保存。
3. 草案保存到既有 GrowthChangeDraft，刷新可恢复已保存内容。只有“确认创建父子任务”才创建正式 Task，随后另行生成、审核并采用日程。
4. 父容器在任务与执行区可展开/收起，显示子任务数、完成比例、预计/剩余/实际投入，以及安排、部分完成、取消等事实。子任务沿用原有反馈、计时、目标与排程。
5. 可从父容器手动增加子任务；没有计划和执行事实的普通任务可显式转为父容器。已有事实的转换安全拒绝，现有记录不删除。

未新增 Scheduler、Provider、UI 框架、状态管理库或业务表。

## 数据结构、事务与统计口径

- Task 新增 `parent_task_id`（可空、自引用 RESTRICT 外键和索引）、`task_kind`（executable/container）、`sort_order`（非负建议顺序）。旧任务默认 executable，ID不变；仅允许顶层容器→可执行子任务，每个容器最多20项。自引用、循环、第三层及违反父 DDL 的子任务均拒绝。
- 父容器的 duration_minutes 保存原始预期，不计入执行工作量；status 保持 todo，进度从子任务汇总。禁止父容器直接完成、取消、计时或提交执行反馈。保留无硬删除 API（405），不静默删除子任务。
- 草案使用 GrowthChangeDraft.scope=task_breakdown，payload 保存 input、content、version 和确认后的 created_task_ids，复用 AssistantSession/AssistantMessage 记录来源。profile/review 旧入口不能确认、编辑或取消拆解草案。
- AI 复用 assistant_ai→claude_client，输出经过 Pydantic 校验。1至20个子任务，标题非空，时长为5至10080分钟的5分钟整数倍；全部 DDL 在未来且子 DDL 不晚于父 DDL。AI不能变更用户输入父 DDL，用户可以显式编辑。无Key返回503 AI_NOT_CONFIGURED，失败不创建正式任务。
- 生成等待期间释放 SQLite 事务，结束后重新检查版本。编辑/确认检查 source_revision 与草案 version。BEGIN IMMEDIATE 串行化确认；父任务、全部子任务、目标上下文、applied状态与 revision 一次提交。第3个子任务写入失败时整树回滚；重复及并发确认返回原任务ID。
- 子任务在创建时复制/关联父目标，后续独立管理，父目标修改不自动传播。count/deliverable 目标按已完成子任务ID计数，time目标按反馈实际分钟计量，父容器没有额外贡献。
- 完成比例为 done 子任务数 / 全部子任务数；取消任务仍在分母，并单列取消数。总预计为子任务初始估时之和；待完成剩余只求和 todo 当前分钟；已记录投入/实际分钟来自未撤回的真实反馈。已安排表示正式计划中存在片段，包含历史，不代表完成。过日历时间和结束计时均不会自动完成任务。
- task_library、attention 与两条排程确认边界排除/拒绝父容器，原来两周联合、5分钟网格、分段、锁定、历史保留、候选校验和原子保存继续复用。创建任务树推进全局版本，旧日程候选不能直接采用。sort_order 不构成强制依赖。

## 已知限制与未覆盖项

- 仅两级、每父20项，不实现强制依赖、甘特图、多人、Dashboard或阶段3。
- 所有AI验收为Mock；真实模型的内容质量、耗时和供应商兼容没有实测。AI功能仍需用户自行配置有效Provider。
- 全局资料版本采用保守失效策略：即使改的是其他任务，旧拆解也须取消重建，避免覆盖新事实。
- 服务器只恢复已成功保存的草案。1.2秒自动保存尚未完成、字段无效或网络失败时，离页/刷新会丢失未保存编辑；界面保留错误和“未保存”提示，应先看到保存成功。不会因刷新自动创建正式任务。
- 目标按创建时继承，不随父目标后续变更自动同步；取消的子任务不当作完成，且保留在完成比例分母。
- 手机验收是浏览器视口模拟，没有实机触控/软键盘及跨浏览器矩阵。没有模拟真实HTTP断网超时；API封装错误测试及后端幂等/并发测试覆盖对应保护。
- 本轮没有在用户正常数据库上实测升级；这是保护个人数据的有意边界。

## 同学审核用 PR 描述草稿

**Title:** Add confirmed task breakdown drafts and two-level task hierarchy

Complex assignments previously had to be managed as independent executable tasks. This change lets users generate or manually build a persistent breakdown, edit it, and explicitly confirm one parent container plus independently scheduled children. Containers are excluded from scheduling and execution metrics; draft versions, serialized atomic confirmation and idempotent retries protect against stale or duplicate writes.

Adds Alembic 0002_task_hierarchy and JSON v2 with strict legacy-v1 conversion. Reuses the existing AI provider, draft store, scheduler, execution feedback and React workbench. Validation: 627 backend tests, 76 frontend tests, production build, isolated migration/restore checks and a real-browser workflow using Mock AI. Live-provider quality and physical mobile devices were not tested.
