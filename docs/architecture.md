# 个人成长助手：现行架构

## 现行三页工作台（2026-10）

React 的 `App` 提供规划、复盘、我的档案三个入口；复盘和档案复用 `WorkspaceChat`，规划保留周日程、任务抽屉和候选比较。页面显示采用北京时间，数据库身份隔离浏览器会话缓存。

FastAPI 将 HTTP 校验交给 routers，排程、业务事务、统计和模型接入交给 services。SQLite 保存任务、课程、目标版本、偏好规则、执行反馈、对话、后台运行和修改草案；显式迁移和备份支持已有数据升级。

规划会话按周组织，复盘按选定周组织，档案跨周保留。AI 返回结构化意图，程序校验引用与字段，草案只写候选数据。用户确认时检查来源版本，在事务内应用相关修改；正式修改使旧候选失效。

助手排程覆盖本周剩余时间与下周，使用 5 分钟网格，优先连续安排，明确允许后才尝试有限分段。均衡、习惯、稳定使用各自固定权重；默认偏好只选择方案，不改写三种策略。目标优先级 1 高于 2、3，仅生效目标参与评分。独立校验完整时长、课程、保护时间、DDL、锁定和过去时间；确认在一个事务内替换两周计划。基础 `scheduler.py` 保留单周连续安排的旧接口兼容。

任务、复盘、档案通过聚合接口读取，执行记录按需加载。启动和命令行共用 Alembic 升级入口，旧库结构检查通过后才迁移；不盲目标记版本。旧 WeeklyPlan 页面已移除，相关纯函数移入 `frontend/tests/fixtures` 供兼容测试。当前规则与实际验收见 [阶段 1 验收](archive/阶段1局部重规划与冲突解释验收.md)。

个人偏好采用稳定类别标识和可编辑规则；软偏好不解除硬约束。执行反馈保存历史快照，统计先由程序计算，再交由 AI 组织解释；未经确认的观察不能自动变为长期习惯。

匿名演示由 `scripts/demo_scenario.json` 定义。正常时钟与数据库不因演示启动改变，私有课程只能显式导入。更多目录见[README](../README.md) 的目录说明。

阶段 0 在现有路由外增加小型 `plan_safety.py`：旧单周 API 使用临时占用阻止过去时间安排，继续复用原 Scheduler 和独立 Validator，确认时重新校验当前数据和课程快照。无法表达的硬时间资料、分段或已开始记录明确拒绝，不覆盖旧正式计划。Assistant 继续使用两周校验器，另核对保留记录确实来自正式历史；已有锁定不能借候选中的重复锁定声明移动。两条路径均保留版本检查和原子确认，无新增表或迁移。

### 阶段 1：局部调整范围

`assistant_state.proposed_world` 同时保留正式两周快照与待确认候选上下文。`scoped_replanning` 根据任务 ref、正式片段全集、当前任务资料、真实规则和本轮动作分类；未受影响且合法的未来任务仅在排程输入的深拷贝中临时冻结，历史与既有保护继续由原机制维护。正式任务的锁定资料不会被临时冻结写回。

仍调用原 `assistant_scheduler.arrange`，保持三种策略权重 `(4,3,3)`、`(6,2,2)`、`(2,6,2)`。策略只在授权范围内评分；偏好或 AI 临时规则不授予扩大范围权限。移动任务数、片段数、配对时间位移和重叠比为观测指标，没有加入新的隐藏权重。

局部失败返回空 items、待处理任务和程序诊断。仅在普通搜索未找到完整方案且有可放开的合法任务时，提供明确的扩大范围操作；搜索预算耗尽单独解释，不声称绝对无解。扩大后仍冻结已开始/锁定的任务。授权来源保存在现有候选 JSON，同一版本草案链可继承，采用、放弃或版本变化后重新从局部开始。

现有 AssistantMessage.content 记录范围摘要校验值，防止候选范围元数据损坏或被移除后退回旧行为。确认时核对标记、来源候选、正式快照摘要，并按当前数据重新分类和校验冻结片段，随后继续阶段 0 的历史核对、完整约束校验和两周原子事务。此标记是数据库内部一致性检查，不能防御同时任意改写数据库多个表的攻击者。

结构化变化与诊断附加到候选 payload；前端 `ScopedChanges` 复用原工作台、周日历和确认流程。没有新增表、迁移、Provider、框架或依赖。JSON 备份自动包含新增元数据；恢复继续使旧候选失效。详细机制和验证见 [阶段 1 验收](archive/阶段1局部重规划与冲突解释验收.md)。

## 分层与运行工具

页面统一通过 frontend/src/api.js 请求；routers 负责 HTTP，services 负责业务，models/schemas 负责数据与契约。排程核心不直接调用模型，等待 Provider 时释放数据库事务；正式修改在版本校验和 SQLite 写事务内完成。所有时间边界使用北京时间，SQLite 时间戳保持 UTC。

旧 `/api/plans` 单周兼容入口继续存在，有独立的安全拒绝与确认复验；当前规划工作台使用 `/api/assistant` 两周候选流程。旧单周 API 的前端纯函数只作为 tests/fixtures 中的兼容测试辅助，不重新挂载旧页面。

Alembic 资源位于 `backend/alembic/`，冻结基线、环境和 revision 按原内容迁移。`scripts/migrate.py` 与启动共用 schema_migrations.upgrade_database，不重新生成基线。备份及导出/恢复格式没有变化；数据库与迁移说明见 [database.md](database.md)。

脚本、约束、演示场景的当前布局见 README。新演示和审计产物进入 scripts/.runtime、scripts/.local；原本地目录不移动。演示路径白名单保留旧库兼容；备份若已存在旧默认目录继续使用，其他安装默认用 scripts/.runtime/backups，显式 SGA_BACKUP_DIR 仍优先。没有受版本管理的运行工具依赖旧目录。

当前没有提交中的 CI 工作流；本地正式测试保留在 backend/tests 和 frontend/tests。可选浏览器和真实模型 smoke 不属于自动核心测试或启动流程。具体 API 见 [api-contract.md](api-contract.md)，历史验收仅保留阶段 0、1 及目录整理记录。
