# AI 个人成长秘书：完整产品框架设计

更新日期：2026 年 10 月 20 日  
文档性质：下一阶段的产品设计蓝图；描述目标形态，不代表相关功能已全部实现。  
适用项目：当前 `v1.1`，在已有 MVP 上升级。

> 一句话介绍：有事情先和秘书聊；需要办事时，在旁边查看、修改并确认；做过的事留下记录，帮助下一次安排。

## 1. 我们准备把产品做成什么

产品面向大学生，帮助处理学习安排、个人目标和生活中的想法。

用户既可以自由提问、讨论困惑，也可以让秘书查看日程、拆解任务、安排时间、整理复盘。聊天是统一入口，日程、复盘和档案是办事工具。

核心使用过程：

```text
说出想法或需求
      ↓
AI 理解；必要时继续询问
      ↓
需要办事 → 打开工作区 → 生成或修改草案 → 用户确认 → 正式保存
      ↓
实际执行并留下记录 → 回顾与交流 → 决定下一次调整

普通提问、自由交流可以一直继续，不必转成任务。
```

### 当前基础与升级内容

| 部分 | 当前基础 | 升级方向 |
| --- | --- | --- |
| 任务与排程 | 已有任务管理、拆解、排程、方案比较和局部调整 | 由统一聊天调用，在工作区中处理 |
| 执行反馈 | 已有状态、实际耗时和计时记录 | 从聊天或任务详情快速填写 |
| 复盘与统计 | 已有统计、目标进展和周复盘能力 | 重组为“回顾＋复盘记录” |
| 档案 | 已有目标、分类、时间偏好、课程和数据管理 | 统一展示，后续加入可管理的长期记忆 |
| 聊天 | 已有业务对话基础 | 升级为自由交流与办事共用的主聊天 |
| 用户与部署 | 当前为本地单用户 | 先预留数据归属，之后加入账号、隔离和部署 |

本文未单独标注“已有”的交互细节，均应按待开发或待验证理解。

## 2. 软件整体布局：四个区域

桌面端布局示意：

```text
┌────────┬──────────────┬──────────────────────┬──────────────────┐
│ 导航栏 │ 会话列表     │ 主聊天               │ 工作区           │
│        │              │                      │                  │
│ 首页   │ ＋ 新对话    │ 提问、聊天、提出要求 │ 日程｜复盘｜档案 │
│ 日程   │ 搜索         │                      │                  │
│ 复盘   │ 置顶         │ AI 回复和操作反馈    │ 查看具体内容     │
│ 档案   │ 最近         │                      │ 编辑和确认草案   │
│        │ 已归档       │                      │                  │
│        │              │                      │ 展开／收起       │
│ 账号区 │              │ 输入框＋后续语音入口 │                  │
└────────┴──────────────┴──────────────────────┴──────────────────┘
```

- 导航栏：选择工具。
- 会话列表：找到之前聊过的事情。
- 主聊天：表达、讨论、指挥秘书办事。
- 工作区：查看和操作具体内容。

会话列表可以收起；工作区可以收起或展开。展开工作区时，可以临时占用主要内容空间；退出展开后恢复聊天布局，保留当前会话和编辑进度。

手机端通过切换会话列表、聊天和工作区展示内容，不把四栏同时挤在一屏。

## 3. 第一栏：导航与首页

| 入口 | 点击后的行为 |
| --- | --- |
| 首页 | 聚焦主聊天；首次进入默认展示今天的日程 |
| 日程 | 打开或切换到右侧日程页 |
| 复盘 | 打开或切换到右侧复盘页，可展开独立阅读 |
| 档案 | 打开或切换到右侧档案页 |
| 底部账号区 | 目前留空预留；后续接入账号和设置 |

首页以聊天为主体，可提供少量快捷入口，例如“安排今天”“看看本周”“聊聊最近”。不另做一套复杂首页看板。

点击导航只切换工具，不自动创建会话，也不清空正在聊天的内容。

## 4. 第二栏：聊天记录怎么组织

### 4.1 列表结构

```text
＋ 新对话
搜索会话

置顶
  本学期的学习安排
  职业方向讨论

最近
  周五课堂汇报
  最近为什么总是拖延
  本周复盘

已归档
```

确定采用“最近＋置顶＋归档＋搜索”。第一版不增加复杂文件夹，也不要求用户先分类。

### 4.2 基本规则

- 一次会话可以持续多天，用户自行决定何时开启新对话。
- 形成话题后生成简短标题，允许重命名。
- 最近会话按最近活动排序；常用会话可以置顶。
- 归档用于收起暂时结束的话题，仍可搜索和恢复。
- 搜索覆盖标题和消息正文，展示匹配片段。
- 支持删除会话；删除范围明确提示，不连带删除已保存任务和日程。

### 4.3 如何方便回看

会话中保留关联入口，例如“打开任务草案”“查看复盘记录”。长期会话可按需生成“会话小结”，概括讨论主题、重要结论和未决定事项，并能返回相关原消息。

会话小结属于辅助回看，不自动变成长期记忆。普通聊天不会自动保存成正式复盘。

## 5. 中间栏：主聊天怎么使用

主聊天支持三类需求，不强迫用户选择模式。

| 需求 | 示例 | 秘书的处理方式 |
| --- | --- | --- |
| 自由交流 | “最近有点迷茫” | 继续交流，理解具体困扰 |
| 查询和解释 | “看看我这周忙不忙” | 查询相关记录，打开日程并解释 |
| 实际办事 | “帮我安排周五汇报的准备” | 补齐必要信息，生成可编辑草案 |

### 聊天中的基本体验

- 回复支持逐步显示，明确区分理解需求、查询记录和计算安排等状态。
- 可以停止回复或取消等待；若业务动作已经保存，应如实展示保存结果。
- 调用失败后保留输入，允许重试；重试不重复创建任务。
- 回复先讲结果，详细依据按需展开。
- 聊天中的业务卡片能重新打开对应工作区内容。
- 切换会话后恢复各自上下文，待确认草案需要重新检查有效性。

### 后续语音输入

先实现“语音转文字→用户检查和修改→发送”。连续语音交流和语音播报后续再评估，不作为第一轮必须交付的内容。

## 6. 右侧工作区：统一的办事桌面

### 6.1 页面组织

顶部保留“日程／复盘／档案”三个页签，每类只保留一页，重复打开时切换到已有页。任务草案放在日程页的相关区域或详情中，不无限新增页签。

### 6.2 打开与切换规则

| 情况 | 工作区行为 |
| --- | --- |
| 首次进入首页 | 默认显示今天的日程 |
| 用户点击导航或页签 | 立即切换对应页面 |
| 用户明确说“查看日程／复盘”等 | AI 打开对应页面，并简短说明 |
| AI 认为某页面可能有帮助 | 给出“打开查看”入口，让用户选择 |
| 用户正在编辑，聊天只是顺带提到其他话题 | 保留当前页面，不随意切走 |
| 收起后再展开 | 恢复刚才的页面、日期和编辑进度 |

切换页签不丢失未提交内容。页面显示“草案”“已保存”或“有未保存修改”等明确状态。

聊天和工作区共用同一份业务内容：聊天修改要求会更新草案；用户手动编辑后，AI 后续操作也以最新草案为准。

## 7. 日程页：从今天到全年

### 7.1 顶部操作

```text
日程                                      展开
[天] [周] [月] [年]
[上一段]       当前日期或范围       [下一段]
                               [回到今天]
```

| 视图 | 展示重点 | 前后切换 |
| --- | --- | --- |
| 天 | 时间轴、课程、任务、空闲时间 | 上一天／下一天 |
| 周 | 每天的安排、空闲和冲突 | 上一周／下一周 |
| 月 | 截止日期、重要事件、每日任务概览 | 上一月／下一月 |
| 年 | 月份概览、重要阶段和长期节点 | 上一年／下一年 |

年视图点击月份进入月视图，月视图点击日期进入天视图。切换视图时围绕当前选中的日期展开。

“回到今天”让各视图回到今天所在的日、周、月或年。第一版先做好可点击按钮；键盘快捷键后续加入，只在日历操作区域生效，不干扰输入。

### 7.2 任务和安排

- 查看任务详情、状态、关联目标和执行记录。
- 支持任务拆解、预计用时、截止日期和偏好。
- 正式安排与待确认草案视觉区分，并展示新增、移动和冲突。
- 提供开始计时、反馈完成、部分完成和调整剩余工作等入口。
- 时间不够时说明原因，由用户决定延期、缩减或取消。
- 计时结束、日历时间过去，都不自动代表任务完成。

**视图范围不等于自动排程范围。**当前排程主要处理本周剩余时间与下周；新增月、年视图不表示系统已经支持全年自动排程。更远期条目和重复课程如何存储、展开，需要开发时单独落实，不能用界面占位冒充已有数据。

## 8. 复盘页：采用已确认的调研后版本

**最终采用“回顾（日／周／月）＋复盘记录”。不采用此前“今日回顾／每周复盘／历史记录”的三入口方案。**

定位：打开就能看到整理好的记录；想深入理解时再与 AI 聊；认可的结论保存下来。

### 8.1 页面入口

```text
复盘
[回顾] [复盘记录]
```

“回顾”默认本周。从聊天明确指定日期进入时，显示对应时间范围。所有入口共用页面与数据，不另做一份聊天专用复盘。

### 8.2 回顾页面

```text
[日] [周] [月]      < 当前日期范围 >      [回到当前]

已记录完成             已记录投入
任务数量               实际用时
尚未反馈的安排                           [补充记录]

时间花在哪里                           [按天／按类别]
一张简单的时间分布图，点击查看对应事项

这段时间做了什么
[全部] [已完成] [部分完成] [待反馈]
任务列表与执行详情                        [查看全部]

目标进展                    有关联目标和记录时显示

[和 AI 复盘]                            [自己写几句]
```

内容规则：

1. **先显示已有事实，不依赖 AI 生成才能阅读。**
2. 完成数量统计可执行任务，避免父任务和子任务重复计数。
3. 用时只统计实际记录，计划时长与实际时长明确区分。
4. “待反馈”不等于“未完成”；没有耗时记录不按零处理。
5. 按完成时间、投入记录时间和原安排时间统计的内容要分别标注，避免混用范围。
6. 点击数字和图表能查看来源；按天、按类别展示共用同一统计范围。
7. 没有关联目标时隐藏目标进展，不要求先创建目标。
8. 详细比较放在按需展开区域，首屏不堆放大量图表。

### 8.3 两种复盘方式

**和 AI 复盘：**携带所选时间范围及相关记录进入主聊天。工作区保留回顾内容，AI 先讲简短事实，再围绕一个具体问题交流。用户可以纠正、补充，也可以只讨论其中一件事。

**自己写几句：**打开轻量文字编辑区，记录感受、结论或想法，不要求调用 AI、不要求填写固定问卷。

### 8.4 保存为复盘记录

聊天中点击“整理为复盘记录”，生成可编辑预览；用户确认后保存。自主书写也可以直接保存。

| 内容 | 保存什么 |
| --- | --- |
| 标题与时间范围 | 便于知道这次回顾的主题和时期 |
| 回顾摘要 | 重要进展和背景 |
| 我的结论 | 用户认可的观察，可修改 |
| 下一步 | 准备尝试的行动，允许为空 |
| 关联内容 | 任务、目标、依据和会话入口 |

观察需要有依据；资料不足时说明不确定，不自动给用户贴人格标签。个人感受可以原样保留，不强制转成改进措施。

### 8.5 复盘记录页面

- 按时间排列，支持搜索及日／周／月筛选。
- 卡片显示标题、时间、短摘要和已选改进行动。
- 打开后查看全文、编辑内容、查看关联任务、返回聊天继续讨论。
- 保存时保留当时的事实摘要和来源范围，后续数据改变不悄悄重写旧总结。
- 重新生成时提示相关记录已更新，保留旧版本或明确显示本次更新。

### 8.6 从复盘进入行动

“保存复盘”与“应用调整”是不同动作。建议可生成任务草案、排程草案或档案变更，检查并确认后再执行。已有任务优先调整原任务，避免重复创建。

空白状态显示“目前还没有足够记录”，提供补充执行情况或自由交流入口。第一版不做综合效率评分、排名或复杂情绪分析。

## 9. 档案页：秘书对我的可靠了解

建议在档案页内部组织以下分区，初期复用已有表单，不强迫用户首次全部填写：

| 分区 | 内容 |
| --- | --- |
| 目标 | 长期目标、每周目标、优先级和进展 |
| 时间与课程 | 课程、固定占用、需要保护的时段 |
| 偏好 | 工作时段、休息习惯、截止缓冲和调整偏好 |
| 记忆 | 用户确认的长期信息，支持查看、修改和删除 |
| 数据管理 | 导出、备份与恢复说明 |

三种信息要分清：

- 当前聊天：用来理解这次交流。
- 正式记录：任务、日程、目标、执行记录等业务事实。
- 长期记忆：用户认可、适合后续使用的信息。

例如，“今天很累”只作为当次表达；“以后周三晚上希望休息”可以提议保存为偏好，确认后生效。

AI 引用个人信息时，可以说明依据并提供修改入口。删除聊天不自动等于删除独立保存的长期记忆，界面应明确说明。

## 10. AI 如何办事，程序如何配合

用四个角色理解系统：

| 角色 | 工作 |
| --- | --- |
| AI | 理解表达、选择工具、整理建议、解释结果 |
| 后端程序 | 查询数据、计算排程、检查条件、执行保存 |
| 界面 | 展示真实状态、提供修改和确认入口 |
| 数据库 | 保存正式记录、会话及相关关联 |

AI 通过明确的工具操作，例如查询日程、读取目标、生成草案、更新草案、汇总回顾和提议保存记忆。

```text
用户提出要求
    ↓
AI 选取相关上下文并调用工具
    ↓
程序计算、校验并返回真实结果
    ↓
聊天说明结果，工作区展示内容
    ↓
用户确认需要落地的业务变更
    ↓
程序保存，双方显示保存结果
```

AI 说“已经完成”不能作为执行成功的依据。正式保存以程序返回结果为准。

只读取当前需要的记录和相关记忆，避免每次发送全部聊天历史。归档和删除范围、长期记忆更新、调用费用等应有清晰的用户说明。

继续复用 React、Python/FastAPI、排程程序和本地数据库等已有基础。模型提供理解和表达能力，排程规则及数据校验继续由程序负责。

## 11. 数据与操作的共同规则

### 11.1 一份数据，多处使用

```text
用户
 ├─ 会话 → 消息、关联业务入口
 ├─ 任务 → 子任务、日程、执行记录
 ├─ 目标、课程、时间偏好
 ├─ 复盘记录 → 事实摘要、结论、改进行动
 └─ 长期记忆

工作区是查看这些数据的窗口，不再复制一套正式数据。
草案是待确认的版本，与已保存内容区分。
```

### 11.2 必须做到的可靠性

- 查看可以直接进行；AI 提议的正式业务变更先展示草案，再确认。
- 手动编辑的“保存”就是明确提交，不层层追加无必要的确认弹窗。
- 切换页签和刷新后能恢复工作进度；旧草案确认前重新核验版本。
- 正在填写的输入与未提交修改要保留；会话删除等操作说明范围。
- 网络中断或重复点击不造成重复任务；可以查询操作是否已经成功。
- AI 超时不丢输入，有明确重试入口；手动功能继续可用。
- 历史记录保持可追溯，纠正记录时让用户知道修改了什么。

### 11.3 数据与隐私

当前主要业务记录在本地保存；使用外部模型会发送相关上下文，不能宣称所有数据都不离开电脑。密钥只由服务端使用，不暴露到浏览器。

未来多用户版需要统一处理：每条数据归属谁、哪些接口可以访问、用户级导出和删除，以及恢复数据的范围。当前整库备份恢复不能直接当成多用户自助恢复。

## 12. 三个完整使用例子

### 场景 A：从聊天到准备汇报

1. 用户说“周五要汇报，现在还没开始”。
2. AI 了解必要信息，并提议拆解。
3. 右侧日程出现任务和安排草案。
4. 用户说“周三晚上留空”，草案同步更新。
5. 用户也能在右侧修改时长；AI 后续读取最新内容。
6. 确认后正式保存，聊天留下查看入口。

### 场景 B：自由交流，不产生额外任务

1. 用户说“我在纠结以后的方向”。
2. 秘书继续交流，必要时引用已确认的相关目标。
3. 用户没有要求安排事情，就不自动创建任务或弹出复盘。
4. 形成有用结论后，用户可以选择保存小结或记忆。

### 场景 C：从回顾到下周调整

1. 用户说“帮我看看这周过得怎么样”。
2. 工作区打开本周回顾，展示任务和实际用时。
3. AI 与用户讨论一项具体困难，用户补充真实原因。
4. 将认可的结论整理为复盘记录并保存。
5. 用户选择一项建议，生成下周安排草案。
6. 确认后应用；复盘记录关联本次调整。

## 13. 开发顺序与上线准备

| 阶段 | 主要交付 | 验收重点 |
| --- | --- | --- |
| 1. 新工作台 | 四区布局、会话管理、页签与现有能力接入 | 能聊天、切换工具、不丢进度 |
| 2. AI 办事 | 工具调用、草案同步、确认保存、回顾页重组 | 完整跑通聊天到日程、复盘到调整 |
| 3. 秘书体验 | 按需上下文、长期记忆管理、异常恢复、移动端 | 多轮交流连续，错误可恢复 |
| 4. 账号与隔离 | 登录、退出、必要的账号恢复、用户级数据权限 | 多人互相看不到、改不到数据 |
| 5. 小范围部署 | 服务部署、备份恢复、日志、额度与试用 | 真实网络与多人使用下稳定 |
| 后续扩展 | 语音输入、更主动的提醒、外部集成 | 根据试用需求安排优先级 |

开发开始就预留用户归属，不等最后再给所有数据补权限。主体开发期间可提前验证部署环境；公开上线放在账号隔离和基本可靠性验收之后。

上线前还要明确模型费用由谁承担、如何限制调用量、用户数据如何删除、出现问题如何恢复。数据库是否需要迁移到服务器型数据库，根据多人部署和并发需求决定，不在本次产品设计中强行指定。

### 核心验收清单

- [ ] 首次进入有聊天入口，右侧默认展示今天日程。
- [ ] 导航、页签和聊天打开的是同一套工作区。
- [ ] 会话可搜索、置顶、归档、恢复和删除，正式任务不随会话误删。
- [ ] 自由交流不被强行转成任务、记忆或复盘。
- [ ] 日程支持天、周、月、年切换，正确展示实际已有数据。
- [ ] 聊天与面板修改共用最新草案，旧版本不能覆盖新状态。
- [ ] 复盘为“回顾（日／周／月）＋复盘记录”，数据来源可查。
- [ ] 未反馈、未完成、没有耗时记录清楚区分。
- [ ] 保存复盘不会自动改变日程，应用调整需要确认。
- [ ] AI 失败、取消、重复请求和刷新不造成数据丢失或重复创建。
- [ ] 长期记忆可查看、修改、删除，临时表达不自动变为长期标签。
- [ ] 多用户上线前完成数据隔离、备份恢复和模型额度验证。
