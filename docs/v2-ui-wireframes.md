# Student Growth Assistant V2：低保真结构原型

日期：2026-10-21。以下是可审核的结构与交互建议，未修改生产前端、安装UI库或创建演示项目。产品依据为本次摘要，未找到完整《v2产品框架设计.md》，尚未逐条对照。所有文字/数据为示意，不来自私人数据库；具体像素、断点、保留期待后续验收确定。

## 1. 默认首页：聊天为主，右侧今日

```text
┌──────┬────────────────┬────────────────────────────┬───────────────────┐
│ 主导航│ 会话       [收起]│ 本次对话                 ⋯ │ 今日 10月21日     │
│      │ [+ 新对话]      │                            │ [收起][展开]       │
│ 首页 ●│ [搜索会话_____] │ 你：帮我看看今天怎么推进。   │ ‹  今天  ›        │
│ 日程  │                │                            │                   │
│ 复盘  │ 置顶           │ 助手：今天有两项待推进。     │ 09:00 ┌课程────┐  │
│ 档案  │  ○ 本周安排    │ 你想先看安排还是讨论任务？   │       └────────┘  │
│      │                │                            │ 14:00 ┌任务────┐  │
│      │ 最近           │ [查看今日日程] [查看任务]   │       └────────┘  │
│      │ ● 本次对话     │                            │                   │
│      │ ○ 项目拆解     │                            │ [任务与执行]      │
│      │ ○ 阅读计划     │                            │ [待确认调整 1]    │
│      │                │                            │                   │
│      │ [已归档]       │ [输入消息________________] │                   │
│      │                │ [发送]                     │                   │
└──────┴────────────────┴────────────────────────────┴───────────────────┘
```

默认打开新壳时右侧是今日，聊天获得主要宽度。后续用户切去别日/复盘/档案后，返回首页恢复上次工作区状态；“回到今天”是显式动作，不因导航点击重置。可在顶栏提供该动作，具体默认恢复优先级按此建议验收。

主导航只管页面/工作区，不自动创建对话或确认草案。会话与工作区各自保留选择；从会话中的“查看日程”卡片跳转可以带明确日期，并保存跳转前位置。普通交流只回复，不出现强制任务/记忆表单。

会话列表的搜索、置顶、归档、删除属于后续会话API能力；现有实现没有这些接口。1A原型可展示结构，开发接入前对应操作禁用/清楚标待接入，不用假的本地列表冒充完成。

## 2. 日历展开：周视图获得主要空间

```text
┌──────┬───────────────┬─────────────────────────────────────────────────┐
│ 导航  │ 聊天（窄栏）  │ 日程                            [普通][收起]     │
│      │ 当前对话      │ [今天] ‹ 10/19—10/25 ›   [天][周●][月][年]       │
│ 日程 ●│               ├─────┬─────┬─────┬─────┬─────┬─────┬─────┬─────┤
│      │ 最近回复      │ 时间│ 周一│ 周二│ 周三│ 周四│ 周五│ 周六│ 周日│
│      │ ……            │ 08  │     │     │     │     │     │     │     │
│      │               │ 09  │课程 │     │课程 │     │     │     │     │
│      │ [待确认调整]  │ 10  │     │任务 │     │任务 │     │     │     │
│      │               │ ··· │     │     │ 当前时间线 →               │
│      │               │ 14  │     │     │任务 │     │     │     │     │
│      │               │ 15  │     │     │┄候选┄│    │     │     │     │
│      │               │ ··· │     │     │     │     │     │     │     │
│      │ [输入_____]   │ [任务列表] [课程/保护时间图例] [待确认调整]       │
└──────┴───────────────┴─────────────────────────────────────────────────┘
  会话列表暂时收起；其展开偏好保留，退出展开后恢复。
```

展开优先保障周列可读；中心聊天保留窄栏和返回入口，窗口不够宽时可切成“返回聊天”按钮。不是给聊天和日历同时强塞固定最小宽度。点击事件打开工作区内详情抽屉；不把任务编辑器永久堆在日历下方。

```text
┌ 事件详情 ─────────────────┐
│ 报告实现 14:00—15:00      │
│ 正式安排 / 第1段，共2段   │
│ [编辑任务] [记录执行]     │
│ [生成调整草案]            │
└──────────────────────────┘
```

课程、正式任务、待确认候选分别有文字和样式标记，不能只用颜色。父容器不占日历；未排程任务列在“任务列表”。待确认overlay不冒充正式日程；保存/采用成功后才更新正式事件。早期只读，后续拖拽也先生成草案并回到明确确认。

## 3. 会话与工作区收起状态

```text
会话展开： [导航] [会话列表  收起‹] [主聊天] [工作区]
会话收起： [导航] [›会话]           [主聊天] [工作区]
工作区收起：[导航] [会话/收起入口] [主聊天占剩余空间] [‹日程]
工作区展开：[导航] [会话收起入口] [窄聊天/返回] [日程占主要空间]
```

会话列表展开/收起和工作区三态是两个独立状态。展开工作区临时压缩会话列表，退出后恢复此前偏好；不能永久覆盖用户的列表状态。保持键盘焦点在触发按钮或可见区域；隐藏的编辑器不能继续接受Tab焦点。

会话行菜单：置顶/取消置顶、归档/恢复、删除。归档保留消息和正式业务记录；搜索默认最近/未归档，可明确包含归档。删除前展示影响：不删除关联正式任务/反馈/计划，有运行或待确认草案时明确处理；删除保留期、最终销毁规则仍需后续产品决定。切到新对话时保留原会话输入，不自动发送。

## 4. 日、月、年浏览

```text
天：[日期] [时段纵轴 + 当天事件] [未安排任务入口]

月：  ‹ 2026年10月 ›             [天][周][月●][年]
      一  二  三  四  五  六  日
      [日期格：课程/任务摘要，最多几条 + 更多]
      点击日期 → 保持选中日期并进入天视图

年：  ‹ 2026年 ›                 [天][周][月][年●]
      [1月小月历] [2月小月历] [3月小月历]
      [4月小月历] [5月小月历] [6月小月历]
      …… 共12个月，有记录的日期显示标记
      点击月/日 → 月/天；不自动生成全年安排
```

年只作概览，详细事件按范围加载；加载中/失败与“无正式安排”分开。课程按当前周期规则展开，若没有学期边界必须说明其依据，不能默认每周课程全年真实有效。切视图保留所选日，范围查询不会改变任务DDL、规划周或生成候选；超出两周规划窗口可查看，调整操作须显示实际引擎支持范围。

这些能力尚待范围API和日历适配，不把当前两周数据外的空白当“全年查询已实现”。

## 5. 聊天与工作区共享草案

```text
中心聊天                         右侧工作区
┌ 待确认：拆解课程项目 ───┐       ┌ 审核拆解 ─────────────┐
│ 3项子任务，预计180分钟  │──────>│ 父标题/DDL             │
│ [在工作区编辑]          │       │ 子项、时长、DDL、顺序   │
│ 草案已更新 / 未确认     │<──────│ 修改尚未保存 / 已保存   │
└───────────────────────┘       │ [确认创建] [放弃]       │
                                └───────────────────────┘
```

两端指向同一草案ID/版本，只有一份可编辑缓冲。工作区编辑成功后聊天卡片摘要同步；不是聊天copy和面板copy独立提交。确认前必须先保存有效编辑；409冲突保留本地内容并提供对照/重新载入，不静默覆盖。不需要把内部ID、revision、数据库字段展示给普通用户。

采用失败/超时：保留输入和预览，显示“保存结果待核对”，按原请求ID查询；不能先显示“已采用”再等网络。放弃只作废草案，不删正式记录。旧版本卡片可看历史，但操作按钮按当前后端状态禁用。

## 6. 复盘：回顾与复盘记录

```text
┌ 复盘 ──────────────────────────────────────────────────┐
│ [回顾●] [复盘记录]                         [展开/收起]   │
│ [日] [周●] [月]          ‹ 10/19—10/25 ›                │
│                                                        │
│ 确认完成 3项     已知投入 180分钟     待补耗时 1条        │
│ [一张趋势图 / 简洁类别分布]                             │
│                                                        │
│ 本期观察                                               │
│ · 依据记录的一条结论                                   │
│ · 一条需要补充的数据 → [补录]                          │
│ [与助手讨论] [生成复盘草案]                             │
│ 更多统计/口径说明（按需展开，不默认堆满）                │
└────────────────────────────────────────────────────────┘

┌ 复盘记录 ──────────────────────────────────────────────┐
│ [按日期/周期筛选]                                     │
│ 10/12—10/18 周复盘   用户已确认   [查看]                │
│ 10/01—10/31 月复盘   草案待审核   [继续编辑]            │
│ 旧版生成的周说明     历史生成记录 [查看]                │
└────────────────────────────────────────────────────────┘
```

回顾是当前有效事实的只读汇总；记录是用户审核后的结论，保留生成时事实快照。点击“生成”只进入草案，“保存复盘记录”才成为正式记录；若想由结论创建下周任务，另行生成并确认任务草案。旧版生成即保存的周说明不能标为“用户已确认”。

默认少量关键事实和可执行入口；缺耗时显示未知/已知小计，不虚构完成率。完成按完成时间、投入按反馈发生时间；当前目标元数据不是历史目标事实。更正反馈后实时回顾变化，已保存记录保留原依据并标注生成时刻，可生成新版，不悄悄改旧结论。日/月能力未接入时明确禁用，不能把4周统计伪装成自然月。

## 7. 档案：固定二级导航

```text
┌ 档案 ─────────────┬───────────────────────────────────┐
│ 目标             │ 目标                       [+新增] │
│ 时间与课程       │ [阅读：每周2篇] [修改]             │
│ 偏好             │ [项目：里程碑]  [查看关联任务]      │
│ 记忆             │                                   │
│ 数据管理         │ 当前仅显示所选二级页正文            │
│                  │ 编辑器在当前页/抽屉内，不跨页堆叠   │
└──────────────────┴───────────────────────────────────┘
```

- 目标：复用现有目标与关联逻辑，父子任务真实进度；不由聊天推测目标已完成。
- 时间与课程：课程、保护时段和导入预览，停用仍保留历史；没有全年排程按钮。
- 偏好：可编辑规则与类别；AI观察先作为待确认建议，不自动升级为长期规则。
- 记忆：后续列表显示内容、来源、确认/更新时间、编辑与删除；尚未接入时显示真实空能力状态，不把ai_note冒充完整记忆系统。
- 数据管理：导出、恢复、备份、说明。恢复前说明覆盖当前资料及待确认草案失效，用户明确操作；不在普通聊天中自动恢复数据库。

固定二级导航取代整页锚点长滚动；切二级页保留目标/偏好/课表的未提交编辑，不因卸载清空。技术字段、统计公式详情和运行信息放帮助/开发文档，仅必要的数据质量提示留在正文。

## 8. 手机端：单视面切换

```text
┌───────────────────────────┐
│ [会话]  本次对话   [工作区] │
│                           │
│ 消息区                    │
│ [查看日程]                │
│                           │
│ [输入消息________] [发送] │
│ [首页] [日程] [复盘] [档案]│
└───────────────────────────┘

[会话] → 全高抽屉/独立视面
  新建 / 搜索 / 置顶 / 最近 / 归档
  选择后返回聊天，保留工作区日期和编辑

[工作区] → 全屏工作区
  [返回对话]  日程  [天/周/月/年]
  详情与表单采用全屏抽屉，周视图局部横滑
```

手机不同时挤四列；会话/聊天/工作区三者切换，各自滚动位置保留。顶部返回、系统返回关闭当前抽屉/编辑层，再回来源，不丢输入。软键盘不遮发送/保存，安全区域留白；触摸和屏幕阅读器需真实验证，不能仅凭媒体查询断言完成适配。

点击聊天卡片打开工作区时记录返回目标，返回聊天恢复原消息位置；新消息不把正在读历史的用户强行拉到底部，沿用“有新回复”入口。

## 9. 状态保留与异常交互验收

| 动作 | 必须保留 | 允许改变 | 明确禁止 |
|---|---|---|---|
| 收起/展开会话列表 | 当前会话、输入、工作区、日期、编辑 | 列表宽度/可见性 | 创建新会话、发送消息 |
| 工作区普通/展开/收起 | 页面、所选日期/视图、表单、草案引用 | 空间分配 | 重置今天、自动保存正式数据 |
| 日程→复盘→档案 | 每页二级状态/编辑缓存、会话 | 活动正文 | 默默丢弃无效/未提交编辑 |
| 切会话 | 原会话输入和归属草案、全局工作区 | 消息/观察中的run | 将迟到回复贴到新会话、自动取消原run |
| 刷新浏览器 | 已保存消息/草案；可恢复本地编辑 | 重新GET并核版本 | 用旧缓存覆盖新服务端数据 |
| 网络失败/确认超时 | 输入/草案/request ID | 错误提示/重新核对状态 | 换ID自动重发正式写入 |
| 资料版本冲突 | 本地编辑用于比较 | 重新读取/另建草案 | 静默覆盖、继续使用过期确认按钮 |
| 恢复数据库/切身份 | 明确提示并隔离旧编辑 | 正式缓存全部失效 | 把旧会话/草案操作应用到新资料 |

“保留未提交编辑”建议分两层：导航/收起期间由壳级registry保留；同浏览器刷新用按workspace/资源分区的sessionStorage恢复候选编辑，重新读取baseVersion后才能保存。无痕清理/浏览器存储失败时要提示不能保证刷新恢复，不能承诺跨设备恢复未提交内容。已保存服务器草案才支持跨设备继续。

## 10. 结构评审清单

审核重点：聊天与工作区是否独立、日历展开是否真正可读、一级/二级导航是否清楚、任务与草案是否区分、复盘记录是否显式确认、手机返回是否保留编辑。参考Notion Calendar的时间网格/事件交互和滴答清单的侧栏组织原则，不复制其商标、图标、品牌资源或源码。

**原型是阶段0交付；不表示对应业务均已实现，完成后等待审核，不进入阶段1。**
